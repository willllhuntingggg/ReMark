# ReMark Welcome Page — Development Prompt

Please build a new **Welcome Page** for the existing ReMark Chrome Extension. This page will be used as the first experience for users after they install the extension.

## 1. Core Objective

The Welcome Page is **not a feature tutorial and not a traditional SaaS onboarding page**.

Its primary purpose is to create an emotional connection with the user and make them feel:

> **“This is exactly what I've been looking for.”**

The core idea behind ReMark is:

> You read, explore, and discover things every day.
> Some things are worth keeping.
> ReMark simply helps you leave a little marker.

Core English brand message:

> **Leave a mark. Find your way back.**

The Welcome Page communicates **WHY** ReMark exists.

The existing three-page GIF onboarding communicates **HOW** to use it.

**Very important: DO NOT modify, redesign, refactor, or replace the existing onboarding.**

The existing onboarding already teaches:

1. How to mark text
2. How to mark moments in videos
3. How to click a Mark and locate the original content

The Welcome Page should only introduce the concept and then connect naturally to the existing onboarding.

------

# 2. Emotional Direction

The overall feeling should be:

- Fresh
- Calm
- Natural
- Beautiful
- Gentle
- Healing / soothing
- Slightly adventurous
- Quietly inspiring
- Relaxed rather than productivity-focused

The user should feel:

> **“I don't have to remember everything anymore.”**

The page should have a strong sense of **airiness** and breathing room.

Avoid the visual density and information-management feeling of products like Notion, Readwise, Evernote, etc.

The experience should feel more like discovering a thoughtful little tool than installing another productivity utility.

------

# 3. Core Metaphor: Trail Marker

Use **trail marker / path / little marker / dot / waypoint / journey / find your way back** as the conceptual and visual language.

However:

### Natural but not literal.

Do NOT turn this into a hiking/outdoor-themed product.

Avoid literal illustrations of:

- Mountains
- Tents
- Hikers
- Backpacks
- Compasses
- Camping gear
- Outdoor landscapes that make it look like a hiking app

The trail marker should remain a **mental metaphor**:

> As you explore the web, when you encounter something worth keeping, leave a small marker. Later, you can follow that marker back.

A small **dot / marker** can become the core visual element of the page.

------

# 4. Page Structure

Do not create a complicated multi-page carousel.

Build the Welcome Page as a calm, immersive, vertically flowing experience with approximately **three narrative sections**.

------

## Section 1 — Discovery

Do not immediately explain what ReMark is.

First, evoke the user's own experience.

Primary copy:

> **Every day, you come across things worth remembering.**

Then:

> A sentence.
> A moment.
> An idea.

Visual direction:

A very thin, subtle path moves through the page.

There are a few tiny marker dots along the path.

Keep the visual extremely minimal.

Do NOT use GIFs here.

Do NOT show feature screenshots.

Do NOT mention:

- Text Highlight
- Video Timestamp
- Side Panel
- Notes
- Shortcuts

The purpose of this section is simply to make the user think:

> “Yes. I come across things like that every day.”

------

# 5. Section 2 — The Problem & The Marker

Let the path continue forward.

The things encountered earlier gradually fade away, leaving only a few small markers behind.

The narrative should move toward:

> **You find something worth remembering.**

Then:

> A sentence.
> A moment.
> An idea.

Then:

> You tell yourself you'll come back to it later.

Then:

> **And then… you can't find it.**

Create a subtle emotional transition here.

Do not use dramatic animations.

For example, previously visible content can gradually fade away while the small markers remain, creating the feeling that the original moment has passed but the marker is still there.

Then introduce the core concept:

> **Leave a little marker.**

Supporting copy:

> When something catches your eye,
> leave a mark.
>
> Like a trail marker on a path,
> it helps you find your way back.

The marker should become the central visual element here.

A single dot can gently light up on the path.

------

# 6. Section 3 — ReMark

Only at this point should the product name become prominent.

Brand:

> **ReMark**

Core definition:

> **A little marker for the things you want to find again.**

You may also use:

> **Leave a mark. Find your way back.**

Do NOT list product features here.

Do NOT write things such as:

- Highlight text
- Mark video timestamps
- Organize notes
- Search bookmarks
- Side panel
- Save everything

This section should communicate only one idea:

> **ReMark lets you leave a small marker on the things worth finding again.**

------

# 7. Connect to the Existing Onboarding

The final part of the Welcome Page should naturally lead into the **existing three-page GIF onboarding**.

Do NOT recreate the onboarding.

Do NOT modify its UI, animations, GIFs, page structure, or interaction logic.

Simply provide a bridge:

> **Ready to leave your first mark?**

Supporting line:

> Let's show you how.

CTA:

> **Show me how →**

When the user clicks this CTA, trigger the **existing onboarding flow**.

The intended experience is:

```text
WELCOME
Why ReMark exists
        ↓
Leave yourself a few markers
        ↓
Show me how
        ↓
EXISTING ONBOARDING
How to mark text
        ↓
How to mark video
        ↓
How to find your way back
        ↓
FIRST REAL MARK
```

------

# 8. Brand Language

Avoid traditional productivity/SaaS language.

Avoid phrases like:

- Save everything
- Organize your knowledge
- Boost your productivity
- Never lose information
- Manage your bookmarks
- Build your second brain
- Capture everything

Prefer language such as:

- mark
- marker
- path
- journey
- find your way back
- come across
- catches your eye
- worth remembering
- worth finding again
- a little marker
- a thought
- a moment
- an idea

The following expressions are especially important and should strongly influence the final copy:

> **A sentence. A moment. An idea.**

> **And then… you can't find it.**

> **Leave a little marker.**

> **Find your way back.**

> **You don't have to remember everything.**

> **Just leave yourself a few markers.**

------

# 9. Visual Design

Overall visual keywords:

### Airy

Large amounts of whitespace.

Do not fill the screen with content.

### Calm

Animations should be slow, subtle, and natural.

Avoid bouncing, aggressive scaling, flashy gradients, or excessive motion.

### Natural

Use soft, organic, low-saturation colors.

### Editorial

Give it a refined reading-product / editorial feeling rather than a dashboard or productivity-tool aesthetic.

### Warm

The experience should feel like a quiet companion for reading and exploring the web.

------

# 10. Color Direction

Continue using the existing ReMark brand color system rather than inventing an unrelated visual identity.

Potential colors include:

- Trail Orange
- Blazing Amber
- Signal Coral
- Atlas Blue
- `#204838`
- `#468282` / “Misty Harbor”

However, the Welcome Page should remain very restrained in its use of color.

Suggested hierarchy:

- Warm off-white / paper-like background
- Deep forest green for primary text
- Very subtle green/blue-green for the path
- Trail Orange / Blazing Amber for the marker accent
- Other colors only as minimal secondary accents

The **marker dot should become the strongest visual signature** on the page.

------

# 11. Motion Design

Keep motion subtle and elegant.

Possible animations:

- The path slowly drawing itself
- Marker dots appearing gradually
- A marker gently lighting up
- Content slowly fading
- Very subtle scroll-driven transitions
- Slow opacity / transform transitions

Avoid:

- Large parallax effects
- Complex 3D effects
- Gamified animations
- Particle effects
- Fast bouncing
- Flashy gradients
- Excessive micro-interactions

The overall feeling should be:

> **Walking quietly along a path.**

Not:

> **Watching a SaaS product launch animation.**

------

# 12. Technical Requirements

This is an internal Chrome Extension Welcome Page.

It does **not** require an external website or custom domain.

Use the existing project's technology stack, component system, styling system, and design tokens.

Do not break any existing extension functionality.

Do not modify the existing onboarding.

Requirements:

- Works correctly as a Chrome Extension page
- Desktop-first
- No external CDN dependencies
- No external website dependencies
- No authentication required
- Can be opened immediately after installation
- CTA can trigger the existing onboarding
- Refreshing the page should not corrupt extension state
- Must remain compatible with the existing Extension ID, manifest, content scripts, and architecture

If the project already has Welcome Page / onboarding state management, reuse the existing logic instead of creating a duplicate state system.

------

# 13. Critical Implementation Constraint

Before making any changes:

**Inspect the existing onboarding implementation and treat it as a protected existing feature.**

Do not refactor or redesign it.

Do not change its UI.

Do not change its GIFs.

Do not change its interaction flow.

Do not change its state logic unless absolutely necessary for integration.

Only add the new Welcome Page and the minimal integration required to launch the existing onboarding.

------

# 14. Final Experience Standard

After implementation, the user should NOT feel:

> “This is a feature introduction page for a Chrome extension.”

Instead, they should feel:

> **“I spend my days reading, exploring, and discovering things.
> I don't need to remember everything.
> I just need to leave a small marker where I want to come back.”**

The ultimate goal is for the user to naturally click:

> **Show me how →**

and then enter the existing three-page GIF onboarding.

**Do not modify the existing onboarding.**

The Welcome Page has one job:

> **Make the user fall in love with the idea of leaving little markers.**

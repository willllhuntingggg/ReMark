# ReMark User Stories

## 文档目的

本文档根据当前代码行为反推产品需求。每条 User Story 只描述一个可独立验收的用户价值，并与一组验收标准成对出现。验收标准采用 Given / When / Then 表达，描述可观察的业务结果，不规定页面布局、事件监听、存储键名或其他实现方式。

本文档不把“标签整理”写成已实现需求：当前代码保存的是划线、笔记和视频打点，未发现可创建、编辑或筛选标签的完整能力，因此不纳入本版本验收范围。

## 角色与术语

| 术语 | 定义 |
|---|---|
| 用户 | 使用 ReMark Chrome 扩展收集网页内容或视频时间点的人。 |
| 划线 | 用户从网页正文中选中的文字片段及其来源页面信息。 |
| 视频打点 | 用户在支持的视频页面记录的当前播放时间点及视频信息。 |
| 页面 | 以 URL 归属的内容集合，包含该 URL 下的划线和视频打点。 |
| 笔记 | 用户附加在划线或视频打点上的文字说明。 |
| 剪藏库 | 侧边栏中按页面归档展示划线和视频打点的内容集合。 |

## User Stories 与验收标准

### US-01：打开剪藏侧边栏

**User Story**  
作为用户，我希望在浏览网页时打开 ReMark 侧边栏，以便查看和管理已经保存的内容。

**Acceptance Criteria**

- **Given** 用户正在使用 ReMark 扩展，**When** 用户点击扩展图标，**Then** 当前浏览器窗口打开 ReMark 侧边栏。
- **Given** 用户在网页上下文菜单中，**When** 用户选择“打开划词灵感侧边栏”，**Then** 当前浏览器窗口打开 ReMark 侧边栏。
- **Given** 侧边栏已打开，**When** 用户重新加载或再次打开侧边栏，**Then** 侧边栏能够读取并展示已有剪藏内容，而不是只展示本次会话新增内容。

### US-02：通过选中文字创建划线

**User Story**  
作为用户，我希望在网页中选中一段文字并保存，以便保留值得回看的原文片段。

**Acceptance Criteria**

- **Given** 当前网页存在至少 2 个字符的可见文字选择，**When** 用户按住 Command 或 Ctrl 完成选择，**Then** 系统保存一条划线，并记录原文、页面 URL、页面标题、创建时间和默认颜色。
- **Given** 用户完成一次有效划线，**When** 保存成功，**Then** 原文片段在当前页面以高亮形式显示，并能在剪藏库中找到。
- **Given** 用户选择为空、少于 2 个字符或没有有效可见区域，**When** 用户使用快捷方式，**Then** 系统不创建划线。

### US-03：通过上下文菜单创建划线

**User Story**  
作为用户，我希望通过浏览器上下文菜单保存当前选中文字，以便在不使用快捷键时完成同样的收集动作。

**Acceptance Criteria**

- **Given** 用户已在网页中选中文字，**When** 用户选择 ReMark 的“划线高亮并保存”菜单项，**Then** 系统保存当前选中文字并在页面中高亮显示。
- **Given** 当前没有有效文字选择，**When** 用户触发该菜单项，**Then** 系统不创建空划线。
- **Given** 划线保存成功，**When** 用户打开剪藏库，**Then** 新划线归属于触发操作的页面。

### US-04：恢复网页中的历史划线

**User Story**  
作为用户，我希望重新访问曾经划线的网页时看到历史高亮，以便快速恢复阅读上下文。

**Acceptance Criteria**

- **Given** 剪藏库中存在某页面的划线，**When** 用户打开该页面或页面在不完整刷新中切换到新的 URL，**Then** 系统尝试在页面正文中恢复对应高亮。
- **Given** 历史划线的原文能够在当前页面正文中匹配，**When** 页面恢复完成，**Then** 该片段显示为与原划线关联的高亮。
- **Given** 历史划线的原文无法在当前页面正文中匹配，**When** 页面恢复完成，**Then** 页面内容不被替换，且该划线仍保留在剪藏库中。

### US-05：查看和定位划线

**User Story**  
作为用户，我希望从剪藏库定位一条划线，以便回到来源页面继续阅读原文。

**Acceptance Criteria**

- **Given** 剪藏库中存在一条划线，**When** 用户选择该划线的打开或定位操作，**Then** 系统激活对应来源页面；若页面未打开，则打开该来源页面。
- **Given** 来源页面已加载且原文可匹配，**When** 定位操作完成，**Then** 页面滚动到该划线，并对目标片段提供短暂的视觉提示。
- **Given** 目标片段尚未恢复，**When** 用户执行定位，**Then** 系统先尝试恢复页面高亮，再继续定位。

### US-06：为划线添加或修改笔记

**User Story**  
作为用户，我希望为一条划线记录自己的想法，以便在以后复习时理解当时的判断。

**Acceptance Criteria**

- **Given** 用户拥有一条划线，**When** 用户保存一段笔记，**Then** 该笔记与这条划线关联，并在剪藏库中显示。
- **Given** 划线已有笔记，**When** 用户保存新的笔记内容，**Then** 原笔记被新的内容替换，且划线本身的原文和来源不变。
- **Given** 用户提交空白笔记，**When** 保存完成，**Then** 系统将该划线视为没有笔记，并显示可再次添加笔记的状态。

### US-07：在支持的视频页面记录时间点

**User Story**  
作为用户，我希望在 YouTube 或 Bilibili 视频播放过程中记录当前时间点，以便以后直接回到关键片段。

**Acceptance Criteria**

- **Given** 用户位于可识别的视频页面且视频元素可用，**When** 用户通过页面中的“打点”能力或 Command/Ctrl+M 记录时间，**Then** 系统保存当前播放时间、视频标识、视频标题、页面 URL 和视频总时长（若可获得）。
- **Given** 当前页面不是受支持的视频页面，**When** 用户尝试使用视频打点快捷方式，**Then** 系统不创建视频打点。
- **Given** 视频当前时间不可用或不是有效的非负时间，**When** 用户触发打点，**Then** 系统不创建视频打点。

### US-08：避免同一视频的近重复打点

**User Story**  
作为用户，我希望重复记录同一视频的相近时间点时不会产生重复内容，以便保持打点列表清晰。

**Acceptance Criteria**

- **Given** 同一视频已有一个打点，且已有打点与当前时间相差小于 1 秒，**When** 用户再次记录，**Then** 系统不新增打点，并将视频定位到已有时间点。
- **Given** 当前时间与同一视频已有打点相差至少 1 秒，**When** 用户记录，**Then** 系统新增一条独立视频打点。
- **Given** 两个打点属于不同视频，**When** 它们的时间相近，**Then** 一个视频的打点不阻止另一个视频创建打点。

### US-09：查看和使用视频打点

**User Story**  
作为用户，我希望在视频进度条和剪藏库中看到视频打点，以便快速回到关键时间点。

**Acceptance Criteria**

- **Given** 当前视频存在已保存打点，**When** 视频页面加载且进度条可用，**Then** 对应打点在进度条的相对时间位置显示。
- **Given** 用户点击视频进度条上的某个打点，**When** 定位操作执行，**Then** 视频跳转到该打点时间；若视频暂停，系统可以继续播放。
- **Given** 用户从剪藏库打开某个视频打点，**When** 来源视频页面已打开，**Then** 系统激活该页面并将视频定位到打点时间；若页面未打开，则打开带有时间参数的来源页面。

### US-10：为视频打点添加或修改笔记

**User Story**  
作为用户，我希望为视频打点记录评语，以便说明该时间点的价值或后续行动。

**Acceptance Criteria**

- **Given** 用户拥有一个视频打点，**When** 用户保存一段笔记，**Then** 该笔记与该视频打点关联，并在剪藏库中显示。
- **Given** 视频打点已有笔记，**When** 用户保存新的笔记内容，**Then** 原笔记被替换，时间点、视频和来源信息不变。
- **Given** 用户保存空白笔记，**When** 保存完成，**Then** 系统移除该打点的笔记内容。

### US-11：按页面归档查看剪藏内容

**User Story**  
作为用户，我希望按来源页面查看划线和视频打点，以便理解每组内容的上下文。

**Acceptance Criteria**

- **Given** 存在来自一个或多个页面的划线或视频打点，**When** 用户打开剪藏库，**Then** 内容按来源 URL 分组展示。
- **Given** 一个页面同时存在划线和视频打点，**When** 用户查看该页面分组，**Then** 两类内容都归属于同一页面分组。
- **Given** 多个页面分组存在，**When** 用户查看剪藏库，**Then** 页面分组按最近一次内容创建时间从新到旧排列。

### US-12：搜索划线和笔记

**User Story**  
作为用户，我希望搜索原文、笔记或页面标题，以便从剪藏库中快速找到相关内容。

**Acceptance Criteria**

- **Given** 用户输入搜索词，**When** 搜索条件发生变化，**Then** 结果只保留原文、划线笔记或页面标题包含该词的页面内容。
- **Given** 搜索词大小写与已保存内容不同，**When** 用户执行搜索，**Then** 匹配结果不受英文字母大小写影响。
- **Given** 用户清空搜索条件，**When** 清空完成，**Then** 剪藏库恢复展示全部页面内容。
- **Given** 页面只有视频打点而没有划线，**When** 用户搜索，**Then** 该页面仍按当前代码规则保留在结果中；视频打点本身不参与文本搜索匹配。

### US-13：删除单条划线

**User Story**  
作为用户，我希望删除不再需要的划线，以便保持剪藏库准确。

**Acceptance Criteria**

- **Given** 剪藏库中存在一条划线，**When** 用户- **Given** 剪藏库中存在䈒线从剪藏库中移除。
- **Given** 该划线当前已在来源页面显示，**When** 删除完成，**Then** 页面中的对应高亮也被移除，而页面原文保持可读。
- **Given** 同一页面还有其他划线或视频打点，**When** 用户删除一条划线，**Then** 其他内容不受影响。

### US-14：删除单个视频打点

**User Story**  
作为用户，我希望删除不再需要的视频打点，以便保持视频回顾路径准确。

**Acceptance Criteria**

- **Given** 剪藏库或视频页面中存在一个视频打点，**When** 用户删除该打点，**Then** 该打点从剪藏库和对应视频进度条中移除。
- **Given** 同一视频存在多个打点，**When** 用户删除其中一个，**Then** 其他打点仍可查看和定位。
- **Given** 视频页面当前打开，**When** 删除完成，**Then** 页面上的打点展示会刷新为最新状态。

### US-15：删除一个页面的全部剪藏

**User Story**  
作为用户，我希望一次删除某个来源页面的全部剪藏，以便清理整组无用内容。

**Acceptance Criteria**

- **Given** 一个页面存在一条或多条划线和/或视频打点，**When** 用户删除该页面，**Then** 该 URL 归属的所有划线和视频打点都从剪藏库中移除。
- **Given** 被删除页面当前在浏览器中打开，**When** 删除完成，**Then** 页面中的 ReMark 高亮被移除。
- **Given** 其他页面存在剪藏，**When** 用户删除一个页面，**Then** 其他页面的内容不受影响。

### US-16：选择页面并导出 Markdown

**User Story**  
作为用户，我希望选择一个或多个页面导出为 Markdown，以便在其他知识管理工具中继续使用。

**Acceptance Criteria**

- **Given** 剪藏库中存在至少一个页面，**When** 用户选择一个或多个页面并执行导出，**Then** 系统下载一个 Markdown 文件。
- **Given** 选中的页面包含划线，**When** 导出完成，**Then** Markdown 包含页面标题、来源链接、划线原文以及非空笔记。
- **Given** 选中的页面包含视频打点，**When** 导出完成，**Then** Markdown 包含视频标题、时间点、可用的视频时长和非空笔记。
- **Given** 用户开启“全选当前显示的页面”，**When** 搜索结果正在生效，**Then** 只选择当前搜索结果中的页面，而不是隐藏页面。
- **Given** 没有选中页面，**When** 用户尝试导出，**Then** 系统不生成空的导出文件。

### US-17：本地保存剪藏数据

**User Story**  
作为用户，我希望剪藏数据保存在当前浏览器本地，以便无需后台服务也能持续使用并减少数据离开设备的风险。

**Acceptance Criteria**

- **Given** 用户创建、修改或删除划线、笔记或视频打点，**When** 操作完成，**Then** 变更在浏览器本地保存，并可在重新打开扩展后读取。
- **Given** 扩展运行环境提供 Chrome 本地存储，**When** 用户使用 ReMark，**Then** ReMark 不要求用户登录或连接后台服务器才能完成核心收集和管理功能。
- **Given** 本地数据不存在，**When** 用户首次初始化扩展，**Then** 系统初始化默认设置，并按当前代码提供演示划线数据。

## INVEST 自检

| 原则 | 本文档处理方式 |
|---|---|
| Independent | 将打开侧边栏、创建划线、视频打点、搜索、删除和导出拆成独立故事，避免把一条完整用户旅程写成一个大故事。 |
| Negotiable | User Story 描述用户价值和结果；不规定 DOM、消息协议、存储字段或具体控件实现。 |
| Valuable | 每条故事都对应用户可感知的收集、回顾、整理或迁移价值。 |
| Estimable | 每条故事边界明确，验收对象单一，便于拆分开发和评估。 |
| Small | 对笔记、定位、删除、去重等可单独交付的能力继续拆分，而不是合并为“管理剪藏”。 |
| Testable | 每条故事都至少有一条 Given / When / Then 验收标准，并覆盖成功、边界或异常场景。 |

## 代码依据

本反推结果主要依据 `manifest.json`、`background.js`、`content/content.js`、`lib/storage.js`、`sidepanel/sidepanel.html` 和 `sidepanel/sidepanel.js` 的现有行为。若未来产品需求与代码行为不一致，应以产品确认后的需求为准，并同步更新本文档与实现。
